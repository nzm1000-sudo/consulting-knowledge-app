# ארכיטקטורת היעד

## זרימת מידע

1. תמלול PLAUD מיובא ידנית (MVP), ובהמשך דרך API או export אוטומטי.
2. שירות עיבוד מסיר מידע מיותר ומחלק את הפגישה למקרים.
3. מודל AI מחלץ אנשים, בעיות, עצות, נימוקים, החלטות, תוצאות, עקרונות וחריגים.
4. כל פריט נשמר ב-PostgreSQL עם קישור למקור ו-confidence score.
5. קטעי טקסט מקבלים embedding ונשמרים ב-pgvector.
6. החיפוש משלב חיפוש טקסט, חיפוש סמנטי וסינון לפי אדם, תאריך וסוג ידע.

## גבולות ה-MVP

הגרסה הנוכחית מדגימה את חוויית השימוש ושומרת מידע ב-localStorage. החילוץ הוא מבוסס כללים ופועל מקומית. אין לשלוח אליה מידע רגיש אמיתי לפני הוספת אימות, הרשאות, הצפנה ומדיניות שמירת מידע.

## שלב ייצור מומלץ

- Frontend: PWA קיימת או Next.js
- Backend: Supabase (PostgreSQL, Auth, Storage, Edge Functions)
- Vector search: pgvector
- AI: חילוץ מובנה לפי JSON Schema, embeddings וחיפוש היברידי
- Security: משתמש יחיד, RLS, הצפנה בתעבורה, מחיקת מידע ו-audit log
